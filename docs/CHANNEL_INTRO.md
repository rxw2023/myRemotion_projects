## 六个元素

### 元素 1 · 地球先生（把头像升格为主角）

**借自**：mg-styles-15 的风格 07「粗描边贴纸人科普 MG」——那支片子证明了一件事：**粗描边 + 两只眼睛，就足以撑起整个片子的情绪**，不需要复杂的角色设计。
**也借自**：RuiC-motion-reel 的第一条硬规矩——**资产要用原始文件，不手画**。所以片头里的地球**不是重画的矢量图，是头像原图本身**。

**独特在哪**：没有第二个频道能把「知识科普」和「一颗有眼睛的地球」绑在一起——地球=世界=知识范围，眼睛=好奇心=主观视角。这是你的昵称「先生」和签名「知识科普向」唯一的视觉正解。

**像素级实测（别改这些数）**：

```
地球圆盘  center = (0.4928, 0.5173)   r = 0.4686   ← 归一化到 300×300 头像
右眼      center = (0.7156, 0.4053)   r = (0.1017, 0.0967)
左眼      center = (0.3402, 0.4636)   r = (0.0900, 0.0917)
```

> 头像里地球的**底部被画布切掉了**，所以圆是用上半圈 + 左右极值做最小二乘拟合出来的（`scripts/channel-intro/make_globe.py`，迭代 24 次）。
> 那个脚本顺手把地球切成了一张 600×600 透明底贴纸 `public/channel/globe.png`（地球内切、圆外 alpha=0）。**这一步是必须的**：如果改成在渲染期用「实测圆心 + 半径」画圆形遮罩，半径只要差 3%，圆外就会露出一圈白纸——而症状看起来像「遮罩没生效」，真因是一个小数。

⚠️ **右眼比左眼高 0.058**，这张脸天生是歪的。**这是签名，不要修。** 所有对称化处理都会让它变成一张没有性格的库存素材。

### 元素 2 · 「二向箔式显影」：线框地球 → 压成平面 → 从平面里印出实心地球

**借自**：RuiC-motion-reel 的印刷管线——明暗拆成四块油墨版、各用不同网线角度做网点、乘法叠印。它最狠的一句话是「**颜色是被算出来的**」，不是调出来的。
**也借自**：mg-styles-15 风格 04 线条动画（line-art）的「线稿自己会长出来」。

**独特在哪**：这是**频道内部的自引用**。你横版那支《二向箔 · 太阳系二维化》讲的就是「三维物体被压成二维」——片头把同一个动作变成了**显影手法**：

```
线框地球自转（三维）
   ↓  经线 rx→0 变成竖直线、纬线 ry→0 变成水平线   ← 这就是二维化
压成一张平面（depth 1→0，8 帧内完成）
   ↓  20px 网屏的网点从 0 撑到 15px
从平面里「印」出真实头像（实心地球）
```

别的频道抄得走网点印刷，抄不走「先把自己压扁再印出来」——因为只有你的作品里有二向箔。

**落地参数**：`depth` 1→0 用 8 帧（约 0.27s，够快才有"压"的暴力感）；网点半径 0→15px，`WebkitMaskSize: 20px 20px`。

> 压扁在几何上是精确的：`depth→0` 时每一条经线的 `rx→0`（塌成穿过圆心的一条竖线，5 条经线重合），每一条纬线的 `ry→0`（塌成一条水平线段，长度 2R·cosφ）。合起来就是球面正对观察者压成一张圆盘——正是二向箔做的事。**不是缩放动画，是投影。**

### 元素 3 · 120 BPM × 5 小节的硬切网格

**借自**：RuiC-motion-reel 的核心方法论——**128 BPM × 8 小节 = 15.000 秒整，一小节一场景，每次剪辑都落在强拍上**。它的立场是「**时间网格先于镜头**」，不是做完再对轴。

**独特在哪**：改一个数就变成你的片头——**120 BPM × 5 小节 = 恰好 300 帧 = 10.000 秒整**，一帧不差地卡在你说的「10 秒左右」。而且 120 BPM 是 B 站口播/BGM 最常见的速度，片头往任何一个成片前面一贴都不会打架。

**所有硬切都落在 15 帧的整数倍上（1 拍 = 15 帧）**：

| 帧 | 秒 | 事件 | 拍位（120BPM） |
| --- | --- | --- | --- |
| 0 | 0.000 | 点阵逐行上电 + 扫描线 | 拍 0 · **小节 1 头** |
| 15 | 0.500 | `> MRDAVE.SYS` 开始打字（2 帧/字符，每个字先乱码 5 帧） | 拍 1 |
| 18 | 0.600 | 16 格进度条开始逐格硬跳（1.5 帧/格） | 拍 1.2 |
| 42 | 1.400 | 进度条填满 → 整条翻绿闪 3 帧 | 拍 2.8 |
| 45 | 1.500 | 绿色 `OK` spring 硬切入 | 拍 3 |
| 75 | 2.500 | 整行上擦 → 线框地球开始生长 | 拍 5 · 小节 2 第 1 拍 |
| 105 | 3.500 | 自转 | 拍 7 |
| **150** | **5.000** | **二维化压扁**（8 帧完成，画面抖 2 帧） | 拍 10 · 小节 3 第 2 拍 |
| 165 | 5.500 | 网点印刷显影 | 拍 11 |
| 180 | 6.000 | 压实（网点撑满 → 实心） | 拍 12 · **小节 4 头** |
| 189 | 6.300 | 眨眼 | 拍 12.6 ← **唯一不在网格上的帧** |
| 195 | 6.500 | 头像框落定 + `MRDave` 硬切入 | 拍 13 |
| 210 | 7.000 | 「先生」盖章（画面抖 2 帧） | 拍 14 · 小节 4 第 2 拍 |
| 240 | 8.000 | 四角套准十字 + 底部签名条 | 拍 16 · **小节 5 头** |
| 270 | 9.000 | 起完全静止 | 拍 18 |

> 最后 1.0 秒完全静止是故意的：贴在任何视频前面时，剪辑师有一整秒不动的画面可以下刀。
>
> **那 2.5 秒的开场为什么只有一行字 + 一条进度条？** 原方案在这里放了一份五行自检清单（`SILICON / MEMORY / MODEL / PIXEL / CURIOSITY`，逐行打勾）。它被整块删掉了 —— 理由记在这里，免得以后有人又想加回来：**清单是在替频道做内容主张**（"我讲硅基/缓存/大模型/前端"），而选题会变、片头不该跟着过期；更要命的是它把片头从 10 秒拉成了"信息图"，观众在读字而不是在看动作。
>
> 删掉之后那 2 秒改成**纯机器动作**：一行 `> MRDAVE.SYS` 打字 + 一条 16 格进度条（见元素 6）。说的是**开机**这件事本身，不是讲什么内容。**结果是片头更硬、更快、更不容易过期。**
>
> 同理，画面上**不放 UID**：UID 是给系统看的，不是给观众看的。
>
> 一句话区分这两者：**清单是"机器在汇报它知道什么"，终端初始化是"机器在动"。前者会过期，后者不会。**

### 元素 4 · 「先生」朱红印章 + 套印错位的字标

**借自**：RuiC-motion-reel 的**乘法叠印**（「粉压蓝是真紫、黄压蓝是真绿」）——它把印刷的物理误差变成了美学。
**也借自**：mg-styles-15 风格 15「综艺花字 hanazi」的字幕冲击力。

**独特在哪 1 · 印章**：你的昵称后缀是「**先生**」。这是一个**中文专属的署名动作**——英文频道做不出来，日文频道会做成「様」，只有中文语境里「先生」既可以是尊称、又能当作一个有点自嘲的江湖名号。所以片头的最后一击是：朱红方章、竖排白文、「先生」二字、`rotate(-3deg)`、砸下时画面抖 2 帧。**这是全片唯一的"手感"，别的都是机械的。**

**独特在哪 2 · 套印错位**：`MRDave` 印三遍——墨色主体 + 海洋蓝向右偏 9px + 大陆绿向左偏 9px，`mix-blend-mode: multiply`。**落定后 3 帧内归零**，变成一块干净的墨。这一下同时完成了两件事：既是印刷厂的味道，又暗示「这频道的画面是**一层层算出来的**」。

**⚠️ 关于朱红 `#E5341C`**：这是全片**唯一一个没有实测来源的颜色**。理由：中文印章的朱砂是**语义色**——它必须像印泥，不能像品牌色。如果您想坚持「100% 实测」，把 `src/ChannelIntro/tokens.ts` 里的 `seal` 改成 `ink` 即可，片头会变成一个纯黑白红的极简版本。

### 元素 5 · 点阵基底：一个点 = 一个 bit

**借自**：mg-styles-15 风格 11「几何构成 / 包豪斯」的网格秩序感。
**也借自**：你自己——`src/CachePrinciple/index.tsx` 里的 `DotGrid` 已经是你的背景语言了。

**独特在哪**：它不只是背景，它有**行为**。开机时点阵**逐行上电**（`reveal` 从 0 爬到 1，像显存刷新），随后整片都活在这个基底上——包括后面从零撑起来的网点印刷，用的是**同一套点阵语法**。于是「点阵」从一个装饰升级成了**一个帧缓冲的隐喻**：屏幕就是一格一格被点亮的。

> **它还有一个隐性工作是补空间。** 删掉自检清单之后，f0–f150 画面里只剩一个终端行和一颗球，上下大片留白 —— 点阵是唯一撑住这个留白的东西。这也是为什么它的透明度只有 **0.55**：再亮就抢戏，再暗就撑不住。

### 元素 6 · 终端初始化：让机器"在动"，而不是"在说"

**借自**：mg-styles-15 风格 08「赛博朋克 HUD / FUI」的系统自检桥段 —— 这跟上面被砍掉的那条**是同一个来源，但取的是不同的东西**。原来取的是它的"清单"（机器说了什么），现在取的是它的"过程"（机器在跑）。**同一个参考换个取法，就从会过期变成不过期。**

**独特在哪**：它把「初始化」拆成三个各自独立、都能一眼认出来的机器动作，而且**三个都不含语义**：

| 动作 | 实现 | 为什么这样 |
| --- | --- | --- |
| **乱码落定** | 每个字落定后先在 `0123456789ABCDEF` 里随机闪 5 帧再锁死 | 十六进制字符集不是"字"，是机器噪声。观众读不出内容，但立刻认得出"终端在刷字符" |
| **块状光标** | 蓝色实心块，停在**下一个要打的位置**，随打字一格一格右跳；打完转 2Hz 闪 | 光标必须跟着打字头走，这是终端光标唯一正确的行为 |
| **16 格进度条** | f18→f42 硬跳填满，填满那刻整条翻绿闪 3 帧，然后 `OK` 落下 | **刻意不做平滑**：一格一格蹦才是"在初始化"，平滑填充看起来像加载网页 |

**三个实现细节，都是踩过的坑：**

1. **字符必须固定格宽。** 整行做成「12 个字格 + 1 个游标格」的等宽网格（`width: cell; textAlign: center`），行宽恒定。否则等宽字体下不同字形的宽度差异会让整行一边打字一边左右抖。
2. **光标不能挂在整行的末尾。** 第一版把游标做成第 13 个 flex 子项，结果它永远钉在**12 格全长的末端**：`MRDAVE.SYS` 才打到第 3 个字，光标已经跑到行尾，中间空一大段。实测证据 —— 逐帧量光标与文字的 x 区间：光标恒在 `684–703`，而文字右边缘从 `301` 长到 `570`。改成「游标占据第 `bornCount` 格」之后，光标跟着打字头走：f10 在 `277`、f16 在 `311`、f24 在 `444`、f32 在 `578`、f48 到行尾 `679`。
3. **乱码必须用确定性伪随机。** Remotion 会在多个进程里逐帧重算同一帧，用 `Math.random()` 会让同一帧每次渲染结果不同，成片会闪。用 `Math.sin(i * 127.1 + 311.7) * 43758.5453` 取小数部分。

> **还有一个只出现一帧的东西**：上电那一帧（f15）整块向左偏 3px 并降 35% 不透明度 —— 一次 CRT 同步抖动。一帧就够，多了像卡顿。

### 附 · 被砍掉的那个元素（自检清单）

> 原元素 5「自检清单」`SILICON / MEMORY / MODEL / PIXEL / CURIOSITY` 已按用户要求整块删除，连同它借自 mg-styles-15 风格 08（系统自检 HUD）与 awesome-opus5-5-videos（清单式开场）的那两条借鉴一起作废。
> 取而代之的是 f15–f75 的一行打字 `> MRDAVE.SYS` + 一条 16 格进度条 + 绿色 `OK`（见元素 3 的时间轴与元素 6）。
> **删它的理由值得留着**：一份清单等于替频道做内容主张，而选题会变、片头不该跟着过期；而且它把观众从"看动作"拉成了"读字"。**借鉴别人的清单式开场是这次唯一一条被砍掉的借鉴 —— 不是它不好，是它跟"片头要能活很久"这个目标冲突。**

## 声音（片头一半的力气在这）

`public/channel/intro-10s.wav` —— **10.0000s / 44.1kHz / 单声道**，纯 Python 合成（`scripts/channel-intro/generate_intro_sfx.py`，numpy 正弦振荡器，**零素材库依赖**，可无限改）。

时间轴严格对齐画面：

| 秒 | 声音 | 对应画面 |
| --- | --- | --- |
| 0.0 | 继电器咔哒 + 50/100/150Hz 电流嗡鸣渐起（ramp 1.3s） | 点阵上电 |
| 0.5 | 打字机瞬态（0.0667s 一个字符） | `> MRDAVE.SYS` 打字 |
| 0.6–1.4 | **上扫正弦**（`300 × 3^prog` Hz，指数上扫） | 16 格进度条逐格硬跳 |
| 1.4 | 一声短促「锁上」咔哒（6.2kHz 低通、5ms 衰减） | 进度条填满翻绿 |
| 1.5 | 1kHz POST 蜂鸣 | 绿色 `OK` 硬切入 |
| 2.5 | whoosh | 整行上擦 → 地球成形 |
| 5.0 | **二维化压扁声** | 压扁 |
| 5.5 | 显影音 | 网点印刷 |
| 6.0 | 压实咔哒 | 压实 |
| 6.3 | 眨眼快门 | 眨眼 |
| 6.5 | 金属切入 | 头像框落定 |
| 7.0 | 盖章闷响 | 「先生」印章 |
| 8.0 | **C5→G5→C6 方波三音动机** | 底部签名条 |

最后那三个音 `C5-G5-C6` 是**可以固定成频道声音签名**的——以后视频里出现「讲清楚了」的时刻，就用这三个音。这是最便宜的品牌资产。

> **音床跟着画面改过一轮。** 删掉自检清单后，原本 2.0s 那四声「逐行通过」的确认音（660/784/880/1046.5Hz）失去了出处 —— 没有清单，就没有"一行一行通过"这回事，留着会是四声莫名其妙的音。它们连同 `confirm()` 函数一起从 `generate_intro_sfx.py` 里删掉了，POST 蜂鸣整个前移到 1.5s，后面所有事件跟着前移半秒到 1.5 秒。**C5-G5-C6 三音动机的位置（8.0s）一动不动** —— 它原来配标语、现在配签名条，但它是声音签名，不该因为画面改字就跟着挪。
>
> **后加的进度条配的是一条扫频，不是 16 声 tick。** 直觉上「一格一声」更贴，但 0.6s 起打字机的瞬态还在响，16 声密集 tick 会和它糊成一片噪声；改成一条 0.6→1.4s 的指数上扫，末端落在一记「锁上」的咔哒上 —— 听感是**一个动作**，不是十六个。这也符合元素 6 的原则：观众听不出有几格，但听得出"在跑"和"跑完了"。

## 怎么用

```bash
# 看效果
pnpm run dev          # 打开 Remotion Studio，选 ChannelIntro / ChannelIntroWide

# ⚠️ 出片前先把 TEMP 指到工作区内，否则 ffmpeg 写不进系统临时目录（见坑 7）
# PowerShell:
#   $env:TEMP = Join-Path (Get-Location) ".tmp"; $env:TMP = $env:TEMP
#   New-Item -ItemType Directory -Force -Path $env:TEMP | Out-Null

# 出片（竖版，贴 B 站视频）
npx remotion render ChannelIntro out/mrdave-intro-10s.mp4 \
  --browser-executable="C:\Program Files\Google\Chrome\Application\chrome.exe"

# 横版
npx remotion render ChannelIntroWide out/mrdave-intro-10s-wide.mp4 \
  --browser-executable="C:\Program Files\Google\Chrome\Application\chrome.exe"

# 验收：画面必须正好 300 帧 / 10.000s，且两条轨都在
node scripts/channel-intro/verify_mp4.mjs out/mrdave-intro-10s.mp4
node scripts/channel-intro/verify_mp4.mjs out/mrdave-intro-10s-wide.mp4
```

当前两版成片（已跑过上面的验收）：

```
out/mrdave-intro-10s.mp4        画面 10.0000s = 300.00 帧  1080x1920  6.68 MB  PASS
out/mrdave-intro-10s-wide.mp4   画面 10.0000s = 300.00 帧  1920x1080  6.52 MB  PASS
```

改设计只动两个文件：

- `src/ChannelIntro/tokens.ts` —— 色板、几何、时间轴 `T`、字体
- `src/ChannelIntro/index.tsx` —— 版式锚点 `buildSpec()`、各元素组件

**几条别踩的坑（都来自 RuiC 的 `gotchas.md` 精神：症状不指向真因）**：

1. **别加辉光。** 纸底亮度约 0.95，任何 bloom 阈值低于 0.95 都会把整帧洗白，看起来像"调色不对"，真因在阈值。想加发光效果先把阈值抬到 0.99 以上。（`tokens.ts` 里 `ALLOW_GLOW = false` 就是这个意思。）
2. **别把 `#242D34` 换成纯黑。** 换了就"脏"。
3. **别把两只眼睛对齐。** 对齐就没性格了。
4. **别在 300 帧之外加内容。** 结尾的 0.5 秒静止是功能性的。
5. **改总时长必须重算音床。** 声音和画面是逐帧对死的，动一个就得动另一个。
6. **别把 `globe.png` 换回渲染期圆形遮罩。** 半径差 3% 就会在圆外露一圈白纸（见元素 1）。
7. **"渲染能出静帧、出不了视频"看 TEMP，不要看输出路径。** 症状是一句 `Error opening output ...\react-motion-renderXXXX\pre-encode.mp4: Permission denied`，看着像输出目录没权限，真因是 ffmpeg 作为沙箱子进程写不进系统 `%TEMP%`。`still` 不走 ffmpeg，所以静帧一直是好的 —— 这个不对称最容易把人带偏。（同一段也写进了 `CLAUDE.md`。）
8. **别拿"容器时长不是 10.000s"当成渲染出 bug。** `mvhd` 取各轨最大值，AAC 每帧固定 1024 采样、ffmpeg 还要在头部塞 2048 采样的 encoder delay，10.000s 的画面配出来的音轨会被凑整成 10.048s（+48ms），于是容器报 10.048s。判据要落在**视频轨自己的 `mdhd`** 上 —— `verify_mp4.mjs` 就是分轨读的，画面 300.00 帧即通过。
