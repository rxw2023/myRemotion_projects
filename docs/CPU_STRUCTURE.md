## 1. 主线：一条总线，两种元件

页面内容很密（两分法 / 数据通路 / 四种组合元件 / 时序元件 / 控制器四步 / 8086 全景 /
寄存器五类 / 段式寻址 / 标志寄存器 / 引脚），平铺会变成"名词表朗读"。
这一期用两条约束把它们串起来：

| 约束 | 推出的东西 |
| --- | --- |
| **内总线同一时刻只能传一个数** | 暂存器 T、三态门、多路选择器、指令队列、CS:IP 拼 20 位 |
| **时序元件必须等时钟节拍** | 组合 vs 时序的分界；谁能当"驿站"、谁只能当"路口" |

于是每个"为什么长这样"的问题都有了答案，而不是记忆点：

- **为什么旧的"运算器 + 控制器"分法不够**：它漏了内总线，而暂存器、MUX 都是总线的产物。
- **为什么 ALU 前面挂一个 T**：两个操作数不能同时上总线，先存一个。
- **为什么 8086 有指令队列**：总线空着的时候顺便把后面的指令取回来。
- **为什么程序计数器在 8086 里不是一个寄存器**：16 位寄存器装不下 20 位地址，只能 CS:IP 拼。
- **哪些寄存器对程序员可见**：指令里能不能点名 —— 看不见的是总线上的搬运工。

收口表（s13）不是背出来的，是问三个问题：靠不靠时钟、记不记得住、能不能点名。

## 3. 取舍

| 取舍 | 理由 |
| --- | --- |
| 不逐个讲 8086 的 40 根引脚 | 页面自己说"了解为主、试题少考"，只保留 AD/A16-19、ALE、中断、READY、HOLD 六组 |
| 乘除法电路、微程序控制器细节不展开 | 属于运算器和控制器两节，这里点到"微指令控制逻辑"即可 |
| 段式寻址只算一个例子（0x1000:0x0023） | 够说明"左移四位再加"，多算会变成算术课 |
| 逻辑地址 → 物理地址不画段重叠 | 8086 段可重叠是另一个话题，与"结构"无关 |
| 条件标志的六个位不逐个举例 | CF/OF 讲透，其余四个给名字和语义即可 |
| 引脚图只画左侧 20 根高亮 | 40 根全标会糊成一片，重点在"复用"这件事 |

## 4. 视觉零件（`src/CpuStructure/parts.tsx`）

颜色语义贯穿 14 场，尽量延续上一期（观众有记忆）：
**总线灰白 / 寄存器蓝 / 内存橙 / 标志黄 / PC 绿 / 控制器紫 / 组合元件青**。

| 零件 | 用途 |
| --- | --- |
| `Bus` | 一句 `drops` 就能给总线挂一排竖线；`hot` 区间高亮"这一刻总线在传谁" |
| `Elem` | 元件框，`clk` 决定右上角有没有方波 —— 全片"会忘/会记"的唯一视觉判据 |
| `ClkIcon` | 方波。s04 放大到 5 倍当主角，s05 挂在 T 上 |
| `Decode` | 译码器：n 位进、2ⁿ 根出，只有一个 Y 亮并带光点 |
| `Mux` | 等距梯形 + SEL 控制线，被选中的那一路会亮 |
| `TriGate` | 三态门：EN 从顶上插进三角形，`open=false` 时输出端画红叉 |
| `RegBank` / `SegMem` / `StackFrames` | 四通用寄存器 / 四段内存 / 三层栈帧（带 BP、SP） |
| `Flags16` | 16 位标志格，9 位有名，其余压暗；每格下标 bit 号 |
| `Add8` | 127+1 竖式，CF/OF 各自着色 |
| `ChipPins` | 芯片俯视图，左右各 20 根引脚，`hot` 高亮一组 |
| `Beats` | 三拍时序横排，每拍写"总线上是谁 / 暂存器怎么动" |

`Elem` 的 `clk` 是这一期唯一的分类开关：有方波的会等节拍，没方波的只看此刻。

  其余句子走缓存，不重复计费

## 6. 自检与踩到的坑

抽帧脚本 `scripts/cpu-structure/stills.mjs`：每场两张 —— 60% 处（看中场元素）与
「场景起点 + 最后一句 + 24 帧」（看收口）。帧号从 `timings.ts` 解析。

这一轮两遍抽帧修掉的问题：

1. **s00 右侧整块图没出现**：容器 `div` 已经 `left:1120 top:396`，里面的 `Elem` 又传了绝对坐标
   → 实际落到 2240，飞出画面。容器改成 `left:0 top:0` 铺满，坐标只算一次。
2. **s01 的 `CPU` 标签压在段首标题上**：标签原在框左上角（128,186），移到框右侧（490,250）。
3. **s02/s05 总线竖线悬空**：`dropLen` 只有 40/46，方块底到总线有 78px 空隙，竖线接不上。
   算清楚再填，别估。
4. **s02"在路径上"三个标注被分叉竖线穿过**：竖线必然穿过方块正下方，标注改到方块**上方**。
5. **s02 控制信号箭头穿过虚线框**：箭头停在框外沿（824），文字挪到箭头右侧。
6. **s03 MUX 与底部大字重叠**：MUX 整体上移 40，大字下移 12。
7. **s04 时钟方波压住说明文字**：scale 7→5（280→200 宽），说明下移 10。
8. **s07 四个控制器框超出外框左边界**（220 < 320）：整体重排成 344/704/1064/1424、宽 320，
   对应箭头也换到 504/864/1224/1584。
9. **s08"不可见"列压着分隔线**：列左移 30，分隔线右移 12。
10. **s08 第四项"T 暂存器"抽帧时还没出来**：`at(8) + 8 + i*6` 的最后一项落在抽帧点之后，
    改成 `at(8) + i*5`。
11. **s09"段起点 0x1000"压在最后一格比特上**：16 格到 818，注释原在 800，移到 870。
12. **s09 CS<<4 那行前 16 位几乎看不见**（`focus` 只亮后四位）：改用 `paint` 给后四位上色，
    整行用暗色，既看得见又不抢重点。
13. **s10 栈帧说明横穿 g() 栈帧**：从 440 移到栈帧正下方 512。
14. **s10"STACK FRAMES" 被断成两行**：`Title` 的英文小字加 `whiteSpace: nowrap`。
15. **s11 标志格上方的分组括号是错的**：条件标志在 bit 11/8/9/7/4/2/0 上不连续，
    一条括号根本框不全 → 整段删掉，只留每格下面的 cond/ctrl。
16. **s12 芯片说明压在芯片框内**：从 (170,700) 移到框外 (200,792)；高亮引脚换成青色才看得见。
17. **s13 表格末行与大字只隔 22px**：大字下移到 818。

最后一轮还删掉两处"看起来像结构、其实是噪音"的线：s01 画面正中那条指向新分法的箭头
（读起来像一条多余的分隔线，语义已由标题说明）、s02 三个问题下方的三条悬空短竖线。

旁白也改了两处（改完只重跑 s03、s06）：

- "准备取**吓**一条" → "取下一条"（错字）
- "输出是 2 的 n 次方**根**线" → "…条线"（"根"当量词读起来会歧义）

> 第三次验证：**大字必须是另一句话**。s03 末句字幕是"它们从不记得上一秒"，
> 大字写成"没有状态，只有此刻"；s05 末句是"ALU 前面几乎一定挂着这么个暂存器"，
> 大字写"补丁，不是花样"。凡是大字等于末句，观众会觉得画面在复读。
